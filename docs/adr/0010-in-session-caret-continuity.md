# In-session caret and keyboard continuity across embedded surfaces

While a document stays open in `office-view-markdown.markdownViewer`, moving the caret or selection across prose, task/list structure, and embedded CodeMirror (and sibling special blocks) must feel like one editor: Arrow/Home/End/Enter/Backspace and mouse enter/leave have deterministic boundary behavior, and the viewport follows the selection in one motion. Logical document position is restored across Lute re-render, lazy CodeMirror mount/teardown, and preview↔edit toggles—presentation remounts must not collapse the caret to block top or invent a second focus ring. Visual contract (with ui): one focus token when crossing surfaces; no “surface selected + inner CM ring” stack; cross-surface highlight stays one family. Explicitly out of this wave: FindBar rewrite (consumes this position contract later), semantic transaction reopen (ADR 0009 already landed), open-document restore (ADR 0008), Welcome/second preview/LLM.
