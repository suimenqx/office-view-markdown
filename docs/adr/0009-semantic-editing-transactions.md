# One user intent is one Markdown transaction

Editing across the WYSIWYG Reading Surface and embedded surfaces (CodeMirror blocks, task/list toggles, link/HTML popovers, special-block chrome) must share one semantic transaction boundary: one user intent produces one canonical Markdown commit, one dirty/save notification, and one undo/redo unit, with a stable document position restored after the commit. Presentation-only work—render remounts, lazy CodeMirror mount/teardown, diagram/image refresh, outline chrome—must never create history or a second dirty pulse. Focus must not decide which history owns Ctrl+Z. Acceptance starts with mixed-surface sequences (prose → code → task → link/HTML → undo/redo → save) on `markdownViewer` only. Explicitly out of this wave: a second preview surface, Welcome, LLM, reopening paste/table or open-document stability, and a full FindBar rewrite (FindBar later consumes this contract).
