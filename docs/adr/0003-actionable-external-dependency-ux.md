# External dependency and media failures must be actionable

When content cannot be shown because of an external capability or media load (PlantUML Server unconfigured or render fail, Mermaid render fail, broken/missing images, and future remote services), the Reading Surface uses one Actionable Empty State family—not a new panel or Welcome-style empty page. Shared contract: short title, secondary explanation (no stack dumps), and a primary next step—**Open Settings** when unconfigured (and never silently hit a public host), **Retry** when configured render or image load fails. Host-side messages use the same contract (`showWarningMessage` with Open Settings). Visual variants stay within the existing AES chrome (info-leaning for unconfigured, warning/error accent for failures). Silent holes, browser broken-image icons as the only feedback, and toast spam are rejected so WYSIWYG editing continues and the next step is always obvious.
